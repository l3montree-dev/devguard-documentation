# Renovate Dependency Proxy Use

[Renovate](https://docs.renovatebot.com/) opens pull requests for new dependency versions. If Renovate looks up versions through the DevGuard dependency proxy, it only sees versions the proxy would also let you install:

- Versions blocked by your [package rules](/how-to-guides/dependency-proxy/package-rules), e.g. a minimum release age, are hidden.
- Versions flagged as malicious are hidden.

Renovate then proposes the newest **allowed** version instead of one your builds would fail to download.

## Supported Ecosystems

| Ecosystem | Renovate datasource | Supported |
|-----------|--------------------|-----------|
| npm | `npm` | ✓ |
| Go modules | `go` | ✓ |
| Maven | `maven` | ✓ |
| Composer | `packagist` | ✓ |
| Debian | `deb` | ✓ (via a custom manager, see [Debian](#debian)) |
| Alpine | `repology` | Not yet, see [Alpine](#alpine) |
| PyPI | `pypi` | Not yet |
| OCI | `docker` | No – version lists are not filtered |

## 1. Get Your Proxy URL

Copy the proxy URLs from the **Dependency Proxy** settings of your organization, project or repository. They contain a secret, which tells DevGuard which package rules to apply:

```
https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/npm/
```

<Callout type="warning">
  Treat the secret like a credential. Everyone who can read your Renovate configuration can use the proxy with it.
</Callout>

## 2. Configure Renovate

Add a package rule per ecosystem to your `renovate.json`:

```json
{
  "packageRules": [
    {
      "matchDatasources": ["npm"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/npm/"]
    },
    {
      "matchDatasources": ["maven"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/maven/"]
    },
    {
      "matchDatasources": ["packagist"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/composer/"]
    }
  ]
}
```

**Go modules** are the exception: Renovate reads the Go proxy from the `GOPROXY` environment variable, not from `renovate.json`. Set it where Renovate runs:

```bash {ignore}
GOPROXY=https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/go/
```

Do not append `,direct`, otherwise Go bypasses the proxy when it rejects a version.

### Debian

Renovate has no built-in manager for Debian packages, for example the versions pinned in a `Dockerfile`. Annotate each version with a comment and let a [custom regex manager](https://docs.renovatebot.com/modules/manager/regex/) pick it up:

```dockerfile {ignore}
FROM debian:trixie-slim

# renovate: suite=trixie depName=openssl
ENV OPENSSL_VERSION=3.5.1-1
# renovate: suite=trixie-security depName=curl
ENV CURL_VERSION=8.14.1-2+deb13u2

RUN apt-get update && apt-get install -y --no-install-recommends \
      openssl=${OPENSSL_VERSION} \
      curl=${CURL_VERSION}
```

The configuration below uses `managerFilePatterns` and needs Renovate 41 or newer. The manager stores the suite as `depType`, so a package rule per suite can point Renovate at the matching proxy URL. Security updates live in the separate `debian-security` archive:

```json
{
  "customManagers": [
    {
      "customType": "regex",
      "managerFilePatterns": ["/(^|/)Dockerfile$/"],
      "matchStrings": [
        "#\\s*renovate:\\s*suite=(?<depType>\\S+)\\s+depName=(?<depName>\\S+)\\s+ENV \\S+=(?<currentValue>\\S+)"
      ],
      "datasourceTemplate": "deb"
    }
  ],
  "packageRules": [
    {
      "matchDatasources": ["deb"],
      "matchDepTypes": ["trixie"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/deb/debian?suite=trixie&components=main&binaryArch=amd64"]
    },
    {
      "matchDatasources": ["deb"],
      "matchDepTypes": ["trixie-security"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/deb/debian-security?suite=trixie-security&components=main&binaryArch=amd64"]
    }
  ]
}
```

A Debian suite lists exactly one version per package. The proxy replaces a blocked version with the newest allowed older one (see [How Debian packages are handled](/how-to-guides/dependency-proxy/setup-proxy/setup-debian-proxy#how-debian-packages-are-handled)), so Renovate proposes this version instead.

<Callout type="info">
  Renovate verifies the downloaded package list against the checksums in `InRelease`, but not the signature. The proxy signs `InRelease` with its own key, so no extra configuration is needed. Only the suites listed in [Setup Debian Proxy](/how-to-guides/dependency-proxy/setup-proxy/setup-debian-proxy#supported-suites) are supported.
</Callout>

### Alpine

Renovate is not supported for Alpine yet. The proxy passes the package index through unchanged and only blocks the download of disallowed versions. Renovate can therefore propose updates that the proxy then rejects with `403 Forbidden`.

## What to Expect

| Situation | Renovate behavior |
|-----------|-------------------|
| Newest version is too young for your minimum release age | Proposes the newest version that is old enough |
| A single version is malicious | Skips this version |
| Newest Debian version is blocked | Proposes the replacement version the proxy lists instead |
| All versions of a package are malicious | The lookup fails and shows up as a warning in the Dependency Dashboard |

<Callout type="info">
  With a minimum release age rule in DevGuard you do not need Renovate's own `minimumReleaseAge`. Renovate never sees the young versions, so it does not open pull requests for them at all.
</Callout>

**Notes**

- Renovate must be able to reach your DevGuard instance. With the hosted Renovate app, the proxy has to be publicly reachable.
- For Go, Renovate additionally contacts `golang.org` and GitHub to find the source repository of a module. Versions are still only read from the proxy.
