# Use Renovate For Dependency Proxy

[Renovate](https://docs.renovatebot.com/) opens pull requests for new dependency versions. If Renovate looks up versions through the DevGuard dependency proxy, it only sees versions the proxy would also let you install:

- Versions blocked by your [package rules](/how-to-guides/dependency-proxy/package-rules), e.g. a minimum release age, are hidden.
- Versions flagged as malicious are hidden.

Renovate then proposes the newest **allowed** version instead of one your builds would fail to download.

## Supported Ecosystems

| Ecosystem | Renovate datasource | Supported |
|-----------|--------------------|-----------|
| npm | `npm` | ✓ |
| Go modules | `go` | ✓ |
| Maven | `maven` | ✓ |
| Composer | `packagist` | ✓ |
| PyPI | `pypi` | Not yet |
| Debian, OCI | `deb`, `docker` | No – version lists are not filtered |

## 1. Get Your Proxy URL

Copy the proxy URLs from the **Dependency Proxy** settings of your organization, project or repository. They contain a secret, which tells DevGuard which package rules to apply:

```
https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/npm/
```

<Callout type="warning">
  Treat the secret like a credential. Everyone who can read your Renovate configuration can use the proxy with it.
</Callout>

## 2. Configure Renovate

Add a package rule per ecosystem to your `renovate.json`:

```json
{
  "packageRules": [
    {
      "matchDatasources": ["npm"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/npm/"]
    },
    {
      "matchDatasources": ["maven"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/maven/"]
    },
    {
      "matchDatasources": ["packagist"],
      "registryUrls": ["https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/composer/"]
    }
  ]
}
```

**Go modules** are the exception: Renovate reads the Go proxy from the `GOPROXY` environment variable, not from `renovate.json`. Set it where Renovate runs:

```bash {ignore}
GOPROXY=https://<your-devguard-url>/api/v1/dependency-proxy/<secret>/go/
```

Do not append `,direct`, otherwise Go bypasses the proxy when it rejects a version.

## 3. Configure Your Package Managers

Renovate updates lock files (`package-lock.json`, `go.sum`, `composer.lock`) with the real package manager. Configure the proxy in your repository as well, so these downloads go through DevGuard too:

- [Setup npm Proxy](/how-to-guides/dependency-proxy/setup-npm-proxy)
- [Setup Go Proxy](/how-to-guides/dependency-proxy/setup-go-proxy)
- [Setup Maven Proxy](/how-to-guides/dependency-proxy/setup-maven-proxy)
- [Setup Composer Proxy](/how-to-guides/dependency-proxy/setup-composer-proxy)

## What to Expect

| Situation | Renovate behavior |
|-----------|-------------------|
| Newest version is too young for your minimum release age | Proposes the newest version that is old enough |
| A single version is malicious | Skips this version |
| All versions of a package are malicious | The lookup fails and shows up as a warning in the Dependency Dashboard |

<Callout type="info">
  With a minimum release age rule in DevGuard you do not need Renovate's own `minimumReleaseAge`. Renovate never sees the young versions, so it does not open pull requests for them at all.
</Callout>

**Notes**

- Renovate must be able to reach your DevGuard instance. With the hosted Renovate app, the proxy has to be publicly reachable.
- For Go, Renovate additionally contacts `golang.org` and GitHub to find the source repository of a module. Versions are still only read from the proxy.
