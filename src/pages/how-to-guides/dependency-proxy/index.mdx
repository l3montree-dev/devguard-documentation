# Dependency Proxy with Malicious Package Firewall

DevGuard includes a built-in dependency proxy that acts as a protective layer between your development environment and public package registries. It helps prevent supply chain attacks by blocking malicious packages before they reach your systems.

## How It Works

1. **Request Interception**: When you install a package, the proxy intercepts the request
2. **Database Check**: The package is checked against the [OSV dataset](https://osv.dev), which includes GitHub malware advisories — kept current via the [vulndb sync](/reference/vulnerability-database/update-schedule)
3. **Blocking**: If flagged as malicious, the request is blocked and logged
4. **Package Rules**: Your [package rules](/how-to-guides/dependency-proxy/package-rules) decide whether the package is allowed, e.g. based on its release age
5. **Caching**: Safe packages are cached with SHA256 integrity verification
6. **Metrics**: All blocked attempts are recorded in Prometheus metrics

## Package Rules

Package rules allow or deny packages with [CEL](https://github.com/google/cel-spec) expressions. They are configured per organization, project or repository and apply to requests using its proxy URL, which contains a secret. Rules are evaluated top to bottom and the last matching rule wins.

A minimum release age is the most common rule. It refuses versions published more recently than a given time, which gives the security community time to detect and flag malicious releases before they reach your teams:

```yaml
rules:
  - name: min-release-age
    action: deny
    expr: pkg.ecosystem != "oci" && now() - timestamp(pkg.releasedAt) < duration("120h")
```

Versions that are blocked are hidden from the package metadata, so version ranges resolve to an allowed version; a download of a blocked version is rejected with `403 Forbidden`. Debian package lists are signed and cannot be filtered, see [Setup Debian Proxy](/how-to-guides/dependency-proxy/setup-debian-proxy#blocked-packages-and-signed-package-lists). OCI registries expose no reliable publish date, so the release age cannot be checked for container images.

See [Package Rules](/how-to-guides/dependency-proxy/package-rules) for the available fields, functions and more examples.

## Cache & Security

The proxy enforces security at the caching layer — malicious packages are never cached, and the database must be fully loaded before any requests are served. See [Cache Management](/how-to-guides/dependency-proxy/cache-management) for details.
